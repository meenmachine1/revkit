# Held-out evaluation

Every revkit gate was first measured on the tuning corpus (`corpus/corpus.json`:
`features`, cJSON, zlib, Lua), and several components' rules were developed
against it: function discovery, decompilation from revkit's own inputs, and
Phase 4 prototype inference. Rates there are in-sample upper bounds. The
held-out set measures the same gates, once, on code nothing was tuned on.

## Policy

- **Never tune on the held-out set.** No rule, prior, threshold, name list or
  baseline in `src/` may be chosen by looking at held-out results.
- Future agents may read the **summary rates** (this note, `scripts/ci.sh
  --heldout` output, `corpus/baselines/heldout-*.json`), but **not
  per-function diffs**: don't run refdiff `--details`, `score.py --examples`,
  `--per-binary` or open per-function outputs on held-out binaries to decide
  what to change. Debug on the tuning corpus; if a held-out number moves, find
  the cause there.
- A held-out baseline only guards against regressions. It is re-saved after an
  intended change elsewhere, never chased.
- If the held-out set ever drives a change, it stops being held out: add new
  projects (a new held-out group) and say so here.

## Matchable functions

The Phase 4 gate, as now defined: **signature match** (types only, names
ignored; `protonorm.signature`), scored on the **matchable subset**, revkit at
least **10 percentage points** above Ghidra, on held-out binaries. The
full-set signature rate and arity are secondary lines.

A function is **matchable** when its truth prototype (the reference notation,
typedefs resolved) names only types a stripped-binary analysis could name:

1. **C primitives**: `void`, `bool`, the integer types in Ghidra's spelling
   (`char`, `uchar`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`,
   `longlong`, `ulonglong`, `__int128`, fixed-width `intN_t`/`uintN_t`), the
   floating types (`float`, `double`, `longdouble`, `_Float16`, `_Float128`,
   `complex`), and `wchar_t`, `char8_t`, `char16_t`, `char32_t`;
2. **libc/OS types**: a struct, union or enum tag or typedef name that the
   target platform's C library or OS headers declare:
   `tools/rk-infer/system_types.txt`, generated by
   `tools/rk-infer/gen_system_types.py` with clang from the headers the
   library signature databases come from (glibc's libc/POSIX/GNU headers for
   ELF; mingw-w64's `windows.h` and msvcrt headers for PE), plus the
   compilers' built-in `va_list` types (`__va_list_tag`, `__va_list`). A
   name counts only on its own platform: `_IO_FILE` on ELF, `_iobuf` on PE;
3. **derived types**: pointers to and arrays of matchable types, and
   anonymous function types (`_func_<ret>_<params>`) whose return and
   parameter types are all matchable.

Anything else makes the function unmatchable: a struct, union or enum the
program declares (`sqlite3 *`, `js_State *`, `mbedtls_sha256_context *`),
an anonymous aggregate (`anon_struct_<hash>`), or `undefinedN`. Function
and parameter names never matter. Functions without a truth prototype (GCC
`DW_CC_nocall` clones) are not scored at all, as before.

The rule is fixed by the type names alone, from headers and the truth, never
from either tool's output, so it selects the same functions for revkit and
Ghidra. It was written down and implemented (`tools/rk-infer/matchable.py`,
`score.py --matchable`, `--gate-subset matchable`) before any revkit score
on the held-out set was computed.

Caveats: a program type that happens to share a name with a libc/OS type
counts as matchable (sources were checked: SQLite's shell redeclares
`DIR`, which is glibc's name too; tcc bundles its own copies of `elf.h` and
Windows headers, whose aggregates are anonymous and so unmatchable anyway);
and a matchable truth can still be out of reach (a `long` vs `int` rank on
LLP64, a `void *` used as something narrower).

## Running

```sh
scripts/build-corpus.sh --heldout --out ~/dev/revkit/out/corpus-heldout   # once; checks the manifest
py=$(scripts/setup-pyghidra.sh)
$py tools/ghidra-export/ghidra_export.py --corpus out/corpus-heldout --out out/ref-heldout \
    --inputs-out out/ghidra-db-heldout -j 7 --heap 4g                     # once
scripts/ci.sh --heldout          # the tuning gates, then the held-out ones
scripts/ci.sh --heldout-only     # the held-out gates alone (no build, tests or tuning gates)
RK_CI_JOBS=16 scripts/ci.sh --heldout-only   # on a shared machine
```

The held-out gates are the tuning gates on the held-out inputs, with
outputs under `build/corpus-out/heldout/` and regression baselines in
`corpus/baselines/heldout-*.json` (`rk-lift`, `rk-lift-analyze`,
`rk-decomp`, `rk-decomp-own`, `rk-infer`). The Phase 4 line is
`score.py --gate-subset matchable --target-gain 10`: reported, and the
baseline guards it, but CI doesn't fail on the 10 pp target. Default
`scripts/ci.sh` is unchanged.

### Bugs found, and what became of them

1. **Decompiler segfault in `Merge::snipReads`** (vendored Ghidra,
   `merge.cc:472` via `Funcdata::opInsertAfter`) on Mbed TLS x86-64
   gcc-O2 debug at `0x10d8e0` (`mbedtls_aria_self_test`) under Ghidra's
   inputs and revkit's own; Ghidra's decompiler process dies on it too.
   Fixed by the decompiler fork's patch 0001 (the function fails cleanly).
   tcc's x86-64 clang-O2, AArch64 gcc-O2 and PE clang-O2 debug builds
   crashed rk-lift elsewhere, in `BitFieldPullTransform::applyRecord`, on
   Ghidra's other three "process died" functions (`struct_decl`:
   `0x130860`, `0x124d60`, `0x14002d7b0`): patch 0002.
2. **Decompiler hang** on MuJS x86-64 clang-O2 debug (Ghidra times out at
   `0x145930`, `jsR_run`): a `RulePtrArith`/`RulePtrsubUndo` cycle. Not
   patched (no iteration cap is both safe and short); rk-lift's
   per-function timeout (30 s by default, as Ghidra's) now stops it.
3. **No crash isolation or per-function timeout**: the timeout came with
   scale2's `DecompileBudget`; isolation is the out-of-process worker's.
4. **rk-infer SIGFPE** in `SplitDatatype::buildPointers` (`subflow.cc`,
   from `RuleSplitStore`) observing `0x107f80` in MuJS x86-64 gcc-O2
   stripped: a locked prototype's pointer to an opaque, size-0 struct.
   Fixed by patch 0003; `src/infer` now rejects degenerate types
   ([infer.md](infer.md)).

The patches, their repros and upstream notes:
[third_party/ghidra/UPSTREAM.md](../third_party/ghidra/UPSTREAM.md).
